# Тестовое задание
## Prayer
Данный проект является тестовым заданием, представляющим собой Flutter-приложение для управления досками задач.

## 🛠 Этапы разработки
Проект был реализован в два этапа, что отражено в истории коммитов:
* Этап 1: Прототип. Реализация базовой логики и управления состоянием с использованием ChangeNotifier (Минимум библиотек).
* Этап 2: Рефакторинг. BLoC + AutoRoute + Интеграция с внешним API (Dio).

## 📝 Функциональные требования
### Навигация и доступ:
* При входе в приложение я как пользователь попадаю на страницу “My Desk”.
* При нажатии на табу “Users Desks” или “Followed” я как пользователь попадаю на страницу авторизации (Auth Guard).
  
### Авторизация:
  * Я могу зарегистрироваться по логину и паролю.
  * Я могу авторизоваться по логину и паролю (данные сессии хранятся в локальном хранилище).
  * Я могу выйти из приложения.
    
### Управление досками (Boards):
* Я могу увидеть список досок.
* Я могу создать новую доску.
* Я могу отредактировать название доски.
* Я могу удалить доску по свайпу.
  
### Управление колонками (Columns):
* Я могу увидеть список колонок внутри доски.
* Я могу создать новую колонку.
* Я могу отредактировать название колонки.
* Я могу удалить колонку по свайпу.

## 🏗 Архитектура
Приложение спроектировано согласно принципам Clean Architecture, что обеспечивает гибкость и тестируемость:
* Data Layer: Реализация API-клиента (Retrofit), репозиториев и моделей данных (DTO). Для работы с сетью используется Dio.
  
* Domain Layer: Содержит бизнес-сущности (Entities) и абстрактные интерфейсы репозиториев. Слой полностью независим от внешних библиотек.
  
* Presentation Layer:
    * UI: Виджеты и экраны.
    * State Management: Реализован на BLoC, что позволяет четко разделять события (Events) и состояния (States).
    * Routing: Декларативная навигация с помощью AutoRoute.
